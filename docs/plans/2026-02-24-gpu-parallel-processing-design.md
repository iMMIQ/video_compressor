# GPU 并行处理设计文档

## 概述

为 GPU 编码模式添加智能并行处理能力，通过动态监控 GPU 利用率自动调整并发任务数。

## 设计目标

1. GPU 模式支持并行处理多个视频
2. 自动探测并设置最佳并发数
3. 持续动态调整以保持高效利用

## 核心架构

```
┌─────────────────────────────────────────────────────┐
│                    主控制循环                         │
│  ┌─────────────┐    ┌─────────────┐                │
│  │ GPU 监控器  │◄──►│  任务调度器  │                │
│  │ (nvidia-smi)│    │             │                │
│  └─────────────┘    └──────┬──────┘                │
│                            │                        │
│              ┌─────────────┼─────────────┐         │
│              ▼             ▼             ▼         │
│         ┌────────┐    ┌────────┐    ┌────────┐    │
│         │ Task 1 │    │ Task 2 │    │ Task N │    │
│         │(编码中)│    │(编码中)│    │(等待中)│    │
│         └────────┘    └────────┘    └────────┘    │
└─────────────────────────────────────────────────────┘
```

## 工作流程

1. **探测阶段**：对第一个视频执行预览编码，同时监控 GPU 利用率变化
2. **计算初始并发数**：根据探测结果估算最佳并发任务数
3. **动态调整阶段**：每完成一个任务，检查 GPU 利用率，根据边际增益决定是否增减并发

## GPU 监控模块

### nvidia-smi 调用

```bash
nvidia-smi --query-gpu=utilization.gpu --format=csv,noheader,nounits
```

### 参数配置

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `cache_duration` | 2秒 | nvidia-smi 调用间隔 |
| `utilization_high` | 95% | 触发减少并发的阈值 |
| `marginal_gain_threshold` | 5% | 边际增益低于此值时停止增加并发 |

## 动态调整策略

### 边际增益判断

**核心思想**：当增加线程但 GPU 利用率不再明显上升时，说明已达到最佳并发数。

```
并发数:    1    2    3    4    5
GPU利用率: 30%  55%  75%  82%  83%
边际增益:   -   25%  20%  7%   1%   ← 增益递减

当增益 < 5% 时停止增加 → 最佳并发数 = 4
```

### 判断逻辑

- **边际增益 < 5%**：保持当前并发数
- **GPU 利用率 > 95%**：减少并发数
- **其他情况**：尝试增加并发数

## 探测阶段

对第一个视频进行特殊探测：

1. 记录编码前的 GPU 基线利用率
2. 执行一次预览编码（5秒）
3. 记录编码期间的 GPU 峰值利用率
4. 计算单任务 GPU 影响值

### 初始并发数估算

```rust
fn estimate_initial_concurrency(probe: &ProbeResult) -> usize {
    if probe.gpu_impact == 0 {
        return 2;  // 默认值
    }
    let estimated = 80 / probe.gpu_impact;
    estimated.clamp(1, 8)
}
```

## 错误处理

| 情况 | 处理方式 |
|------|----------|
| nvidia-smi 调用失败 | 回退到保守模式（并发数=1） |
| 单个编码任务失败 | 记录错误，继续处理其他任务 |
| 探测失败 | 使用默认并发数=2 |

## 边界限制

```rust
const MIN_CONCURRENT: usize = 1;   // 最小并发
const MAX_CONCURRENT: usize = 8;   // 最大并发
```

## CPU 模式行为

CPU 模式保持原有行为：
- 默认 `--jobs=1`（libx265 已自动利用所有 CPU 核心）
- 不自动调整并发数
